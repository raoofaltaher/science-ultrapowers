# Testing science-ultrapowers

There are three kinds of tests.

## 1. Shell tests: `tests/<area>/test-*.sh`

- `tests/claude-code/`: plugin shape. Version sync across manifests, session primer size and its track table (the five track skills and the registration skill named), session-start output, the disclosure check (`test-no-foreign-harness.sh`), the terminology test (`test-terminology.sh`, below), the lab templates (`test-lab-templates.sh`: the table headers, among them the decision log and the request queue, and the stage value `none (an external manuscript)` of the task report), the lab-memory hooks (`test-memory-hooks.sh`: reminder and post-compaction, silent without lab memory, junctions, a closed stdout), the skill content (`test-skill-content.sh`: no old skill names, trigger-only descriptions, the load-bearing sentences in the skill that owns each, among them the lifecycle sentences of `running-the-lab`, `preregistering-the-protocol`, `recording-findings` and the five track skills, the 18,000-byte cap on `running-the-lab`, bare script and skill names, cross-references that resolve to a skill folder or an agent id, a task assignment line that names its task as `<TASK-id>` or `TASK-NNNN`, no doubled "the", and a `PENDING` list of names not yet created, empty since the track skills exist), the adopted skills (`test-vendored-skills.sh`: the lab addendum, cleanliness, provenance hashes, for the fourteen adopted before 0.2.0 and the two adopted in 0.2.0, `investigating-anomalous-results` and `establishing-feasibility-first`, with the verbatim license file of an adopted skill exempt from the harness scans), the agent contract (`test-agents.sh`: frontmatter shape, preloaded skills that exist, the fourteen ids and the manifest list, `Agent` disallowed for the twelve, the `When to invoke` section, the `Contributor Roles Taxonomy (CRediT)` section with its exact line for each role, the lifecycle duties of seven roles (the adopted skills, the registration skill and the lifecycle phrases each role carries), and the lead-session line of `running-the-lab`), the repository documents (`test-repo-documents.sh`: README sections, the credit line, the license, the community files, the terminology standard and the output style file, the self-contained banner SVG, the release notes, the manifest license field, the ignore rules, the workflow permissions block), the environment script's dry run (`test-setup-env-dryrun.sh`: `setup_lab_env.ps1 -DryRun` under `pwsh -NonInteractive` writes nothing and asks nothing; skipped when pwsh is absent); also `run-tests.sh`, the runner itself.
  - `test-terminology.sh` keeps the plugin's own text to `docs/science-ultrapowers/terminology.md`. It scans the nineteen lab skills, the addenda of the adopted skills and, in full, the two adopted skills reworded into the standard (`investigating-anomalous-results`, `establishing-feasibility-first`), the agents, the lab templates, the four documents (`README.md`, `CONTRIBUTING.md`, `AGENTS.md`, `docs/testing.md`), the hooks, the string constants of the lab scripts, and the lifecycle design and plan. It reads three lists from the standard, each in the fenced block after its marker comment: the not-approved terms, the British spellings and the abbreviations. It refuses a not-approved term, a stage code, a British spelling, and an abbreviation that is not expanded at its first use in a file. `tests/terminology-allow.txt` lists the paths still to be renamed; a listed path with no remaining hit fails the test. A line that ends with `<!-- legacy -->`, `# legacy` or `// legacy` is skipped. Two controls prove the matcher: one feeds it four known violations and fails if it misses one; the other checks the hyphen rule (a hyphen joins a word only inside a file name, a path or a code span). `--list` prints the scanned files and exits. `TERMINOLOGY_STANDARD` and `TERMINOLOGY_ALLOW` override the two paths, which the test of the test uses.
  - `test-lab-templates.sh` checks the template tree: the new folders and files exist and the old ones do not, the table headers and the status words are the standard's, the hypothesis record has its fields, the protocol template has its design-validation lines, the adversarial review and the referee report list the ten critical-appraisal domains, the findings log has `Basis` and the experiment register has `Input checksums` and the `feasibility` status, the four lifecycle templates exist (the protocol-adherence review, the response matrix, the synthesis matrix and the archive manifest), `lab.json` has its keys (`tracks` and `preregistration` included), and no template holds a stage code or a not-approved word.
- `tests/hooks/`: session-start behavior, including an empty PATH, a closed stdout and no forks, a plugin root with a space; `run-hook.cmd` on Windows.
- `tests/version-bump/`: `scripts/bump-version.sh`.
- `tests/shell-lint/`: `scripts/lint-shell.sh` (the test stubs shellcheck; the script itself needs it).
- `tests/skill-layout/`: no development files inside skills.
- `tests/skill-size/`: every SKILL.md is under 20,000 bytes.
- `tests/systematic-debugging/`: `find-polluter.sh`.
- `tests/writing-skills/`: `render-graphs.js`; the rendering cases skip without Graphviz.

## 2. Python unittest: `skills/<skill>/scripts/tests/test_*.py`

`skills/saving-artifacts/scripts/tests/` (the artifact archive, `artifacts.py`: `save --task`, `provenance`, `findings add | list | review`, `respond`; `test_terminology_rename.py` checks that each new name works, that the 0.1 verbs stay as hidden aliases, that legacy values are read and reported with the new word, and that a lab in the 0.1 layout exits 2 with the migration message), `skills/verifying-evidence-by-doi/scripts/tests/` (`verify_doi.py`), `skills/deciding-with-jev/scripts/tests/` (`jev_ask.py`, offline), `skills/searching-the-literature/scripts/tests/` (`search_openalex.py`, offline), `skills/initializing-a-research-lab/scripts/tests/` (`init_lab.py`: a fresh folder, an existing project, connectors, permissions, restricted folders; `test_init_migration.py` runs a lab in the 0.1 layout through the shown plan, the renames, the header and status-word rewrites, the archive patterns in `.gitattributes`, the `lab.json` keys and the hand copies of old role ids, and checks that a second run changes nothing; `test_init_output_style.py` checks that the Scholarly Explanatory style is installed, never overwritten and also installed in a migrated lab; `test_init_track.py` checks that `--track` writes the minimal lab of each track, that `tracks` in `lab.json` grows by union and that `--track` on a full lab adds only the track; `test_init_columns.py` checks that the `Basis` and `Input checksums` column additions fill existing rows (`exploratory` and empty), also run on a lab with the new layout, and that a second run plans nothing; `test_init_claude_section.py` checks that a stale lab section between the markers is refreshed and the rest of the file is untouched, that a file that is not UTF-8 is left byte for byte with a warning, and that a re-run keeps the recorded name and short name; `test_init_track_texts.py` checks that each track's lab holds every path the shared texts name (the lab section, `holding-lab-meetings` and `requesting-reference-access`); `test_init_migration.py` also checks that the migrated table headers equal the template headers, that a rename blocked by an open file warns and a re-run finishes it, and that a table rewrite that fails warns and leaves the file unchanged; each test runs the script in a temp folder), `skills/preregistering-the-protocol/scripts/tests/` (`preregister.py`; `test_preregister.py` runs each case in a temporary git repository: `register` makes the registration commit and the time-stamp commit with their trailers, leaves other staged changes alone and refuses a tracked protocol, a protocol path with spaces works, and `check` reports the five items (`registered`, `timestamp`, `unaltered`, `chronology`, `inputs`) as clear, not clear or unprovable, with an output on a parallel branch reported as unprovable; `preregister.py` also finds the registration commit by its trailer, so a copied or renamed protocol works; compares the working copy through git's filters, so `core.autocrlf` reports no false `not clear`; and puts the stamp after a YAML frontmatter block), `skills/synthesizing-the-literature/scripts/tests/` (`flow_diagram.py`; `test_flow_diagram.py` checks that the counts add up from box to box, that the Preferred Reporting Items for Systematic reviews and Meta-Analyses (PRISMA) 2020 and Consolidated Standards of Reporting Trials (CONSORT) styles each write one standalone SVG file, and that counts which do not add up exit 1 with the box named), `skills/migrating-from-claude-science/scripts/tests/` (`migrate_claude_science.py` against a fixture database built from the CREATE TABLE statements recorded in `docs/science-ultrapowers/claude-science-schema.md`; the real database is used only by the dry run recorded in `docs/science-ultrapowers/evals/migration-dry-run.md`). The runner discovers them per directory. `skills/svg-primitives/tests/` is the adopted upstream pytest suite, not run by the lab runner.

## 3. Node tests: `skills/<skill>/scripts/tests/*.test.mjs`

`skills/remembering-for-the-lab/scripts/tests/memory-lint.test.mjs` (the lab-memory consistency check). Run with `node --test`.

## Behavior tests for skills

Baseline and with-skill pressure transcripts live under `docs/science-ultrapowers/evals/<skill>/`, one folder per skill with the scenarios, the runs and the grading; `docs/science-ultrapowers/evals/README.md` lists them all.

## How to run

Everything:

```
bash tests/claude-code/run-tests.sh
```

One file:

```
bash tests/claude-code/test-version-sync.sh
```

## Requirements

Git Bash, jq, node 22+, Python 3.11+. shellcheck and Graphviz are optional for the tests (shellcheck is needed to run scripts/lint-shell.sh itself).
